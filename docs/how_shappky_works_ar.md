# كيف يعمل شابكي

يتميز تطبيق شابكي بالسرعة في قتل التطبيقات، وبالتحديد الدقيق للتطبيقات التي تعمل في الخلفية، على عكس تطبيقات إدارة المهام الأخرى.

تقوم التطبيقات الأخرى عادةً باستعمال صلاحية `Usage Status` وقراءة بيانات الاستعمال، ثم البحث عن قيمة `is stopped`. وإذا لم تجدها، تقوم بتعيين التطبيق كتطبيق يعمل في الخلفية. لكن هذه الطريقة خاطئة؛ فهذه التطبيقات قد لا تكون تعمل في الخلفية على الإطلاق، ومع ذلك يتم قتلها بدون أي فائدة.

يعتمد شابكي بدلاً من ذلك على صلاحية **شيزيكو (Shizuku) / الجذر (Root)** لقراءة معلومات العمليات النشطة مباشرة عبر الأمر `ps`.

---

## 1. تطور خوارزمية تحديد التطبيقات

### الطريقة القديمة (قبل التحديث v2.0.0)
في البداية، كان يتم تحديد التطبيقات النشطة عبر استعلام العمليات باستخدام الأمر التالي:

```bash
ps -A -o rss,name | grep '\.' | grep -v '[-@]'
```

* `-A`: لإظهار جميع عمليات النظام والمستخدم.
* `-o rss,name`: لتغيير شكل النتيجة وإظهار كمية الذاكرة العشوائية المستهلكة (RAM) واسم العملية.
* `grep '\.'`: لإظهار الأسطر التي تحتوي على نقطة، لاستهداف حزم التطبيقات مثل `com.dev.example`.
* `grep -v '[-@]'`: لإخفاء أي سطر يحتوي على الرمز `@` الخاص بالخدمات مثل `example.service@...`.

> **المشكلة:** كانت هذه الطريقة تتخطى الأسطر التي لا تحتوي على نقطة، حتى وإن كانت العملية تخص تطبيقاً (مثل العمليات الفرعية `0 sh`).

### الخوارزمية الحديثة (التحديث v2.0.0 وما بعده)
في التحديث 2.0.0، تم إعادة تطوير الأمر لحل مشاكل التوافق والدقة بين مختلف الأجهزة:

```bash
toybox ps -A -o %cpu,pid,user,rss,name,uid
```

* **أمر `toybox` المدمج:** تم دمج أداة `toybox` داخل الـ APK لضمان توحيد سلوك الأمر واستقراره على جميع الأجهزة والرومات.
* **توسيع البيانات المستخرجة:**
  * `user`: لتحديد اسم المستخدم للعملية.
  * `%cpu`: لتحديد استهلاك المعالج.
  * `pid`: لتحديد رقم العملية.
  * `uid`: لتحديد رقم المستخدم.

## 2. خوارزمية تحليل النتائج

يقوم شابكي بمعالجة المخرجات القادمة من أمر `ps` عبر الخطوات التالية:

1. قراءة أسماء العمليات والتحقق مما إذا كان التطبيق مثبتًا على الجهاز.
2. إذا لم يكن التطبيق مثبتًا، يتم تخطي العملية.
3. إذا كان التطبيق مثبتًا، يتم استخراج اسم المستخدم الخاص بالعملية (مثل `u0_a123`).
4. ربط اسم المستخدم بحزمة التطبيق المثبت.
5. البحث عن جميع العمليات الأخرى التي تعمل بنفس اسم المستخدم.
6. تعيين كافة العمليات المطابقة كعمليات تابعة للتطبيق، مع تخطي أي اسم مستخدم لا يبدأ بـ `u0_` أو يخص النظام.

### المقايضات التقنية والحالات الخاصة
تطابق اسم العملية `name` قد يطابق أحياناً عمليات تم تشغيلها بواسطة تطبيقات أخرى. وعلى الرغم من أن التحويل إلى `user` حل هذه المشكلة، إلا أنه أظهر مشكلة جديدة مع تطبيقات النظام التي تنفذ عمليات باسم مستخدم مشترك مثل `system`. لذلك، يعتمد شابكي بشكل أساسي على `name` لضمان استقرار النظام.

---

## 3. تصنيف التطبيقات وحمايتها

يقوم شابكي بتصنيف التطبيقات إلى:
* **تطبيقات المستخدم (User Apps):** التطبيقات التي قام المستخدم بتثبيتها.
* **تطبيقات النظام (System Apps):** التطبيقات المثبتة مسبقاً من النظام أو الشركة المصنعة.
* **التطبيقات المستمرة (Persistent Apps):** يتم تحديدها عبر أعلام (Flags) نظام أندرويد (وتعيد تشغيل نفسها تلقائياً عند قتلها).

### تحديد التطبيقات الشغالة في الواجهة (Foreground)
لا تعتبر الواجهة صنفاً ثابتاً، بل يتم التحقق من حالتها ديناميكياً عبر:

```bash
dumpsys activity services com.example | grep isForeground=true
```

### التطبيقات المحمية افتراضياً
لضمان استقرار النظام وعدم إزعاج المستخدم، يقوم شابكي بحماية التطبيقات التالية تلقائياً:

1. **تطبيق شابكي نفسه:** لضمان عدم قتل التطبيق لنفسه.
2. **واجهة النظام الحالية (Launcher):** لمنع إعادة تحميل الشاشة الرئيسية.
3. **خدمة الخلفية الحالية (Background Service):** لضمان استمرار عمل التطبيقات الأساسية.
4. **لوحة المفاتيح الحالية (IME):** لمنع تعطل الإدخال.
5. **الويدجتس النشطة (Widgets):** يتم استخراج التطبيقات التي يستعمل المستخدم ويدجتس خاصة بها حالياً عبر:
   ```bash
   dumpsys appwidget
   ```
   *(ضمن قسم `AppWidgetIds`)*
6. **خدمات نظام أندرويد:** لمنع حدوث أخطاء في النظام.
7. **خدمات جوجل:** لضمان استقرار الأنظمة التي تحتوي على خدمات Google.
8. **التطبيقات المستمرة:** لأن قتلها بدون فائدة وسوف تعيد تشغيل نفسها فوراً.

## 4. مراحل قتل وإيقاف التطبيقات

يعتمد شابكي على 4 مراحل متدرجة لقتل التطبيقات التي تعمل في الخلفية:

### المرحلة 1: القتل الناعم (Soft Kill)
```bash
am kill com.example
```
إيقاف خفيف للتطبيق في الخلفية. إذا كان التطبيق يحتوي على ويدجت مستخدمة أو يعمل في الواجهة، فإن القتل الناعم يوقف عمليات الخلفية دون تعطيل الويدجت أو مقاطعة المستخدم.

### المرحلة 2: الإيقاف الإجباري (Force Stop)
يتم التحقق أولاً مما إذا كان للتطبيق عملية نشطة:
```bash
pidof com.example
```
في حال ظهور رقم PID، يتأكد التطبيق أن القتل الناعم لم يكن كافياً، فينتقل إلى الإيقاف الإجباري:
```bash
am force-stop com.example
```
ويقوم بإجبار التطبيق على التوقف كلياً بغض النظر عن حالته.

### المرحلة 3: القتل القسري للعمليات (Signal Kill)
في حال فشل الإيقاف الإجباري وظلت هناك عمليات فرعية نشطة، يتم اللجوء إلى القتل القسري المباشر:
```bash
pkill -9 pid
```

### المرحلة 4: القتل الناعم الشامل (Kill All)
عندما يقوم المستخدم بالضغط على زر "تحديد الكل" ثم "قتل"، يقوم التطبيق بعد إيقاف التطبيقات المحددة بتنفيذ أمر شامل:
```bash
am kill-all
```
وهو قتل ناعم لجميع التطبيقات في الخلفية لتحرير الذاكرة دون التسبب بأي أضرار للنظام.
